# 白皮书：从失败到 DeepSeek-R1-Distill-Qwen-14B 古籍句读训练路线

版本：v1.0（2026-08-02）

## 1. 摘要

今日实验证明：1.5B 模型不适合古籍整页 OCR 转录，但适合短文本句读。
本文基于今日全部失败证据，给出以 **DeepSeek-R1-Distill-Qwen-14B** 为基座、
在原有 CNBE 知识与数据基础上继续训练的完整路线，目标是让模型成为
“古籍句读与智能分段专家”，并保持 CNBE-32 编码知识不回退。

## 2. 今日失败复盘

| 实验 | 指标 | 结论 |
|---|---|---|
| PaddleOCR 整页识别 | 覆盖率 18.05% | OCR 只做定位与兜底 |
| DeepSeek-OCR v1 去重 | 覆盖率 37.76% | 可作兜底，不能作真值 |
| DeepSeek-OCR-2 | 连续空返回 | 暂不可用 |
| 1.5B v3 聊天模板 600 步 | 约 21.27% | 生成式整页修正失败 |
| 1.5B v4 原始续写 1000 步 | 约 20.31% | 生成式整页修正失败 |
| 页面锚定真值库 | 100% 命中 | 唯一可靠路径 |
| 识典公开全文交叉验证 | 100% 逐字一致 | 真值库可外部扩展 |
| 规则句读基线 | F1=0.0933 | 需要模型显著提升 |

失败原因可归纳为四类：任务错配、输入脏数据、推理模式干扰、长样本退化。

## 3. 架构原则（不变）

```text
图片 -> 大字锚点定位 -> 真值库(100% 纯文本) -> 句读模型 -> CNBE 结构化对象
```

- 转录准确性由 OCR + 真值库保证；
- 阅读顺序由几何规则保证；
- 大模型只负责真值文本的句读与分段；
- CNBE-32 挂载 punct 与 sentence_span。

## 4. 为什么选择 14B

1. 1.5B 在 400+ 字目标上已实测失效；
2. 句读是语义任务，14B 的上下文理解与古文语感显著更强；
3. 4-bit QLoRA 下 14B 可在 16-24GB 显存训练，部署成本仍可控；
4. 短样本（80-150 字）下 14B 可实现高精度标点预测，且不出现长文本重复。

## 5. 训练路线

### 5.1 基座与继续训练

- 基座：`deepseek-ai/DeepSeek-R1-Distill-Qwen-14B`（或本地镜像）。
- 与 0.8B 原 CNBE 模型架构不兼容，不能直接复用权重，因此采用**知识迁移**：
  训练数据中混入原 CNBE 178K 数据集（每轮 10,000 条），让 14B 重新掌握
  8,105 字编码知识。
- 若后续产出 14B 版 CNBE 适配器，可走 `optional_adapter` 叠加路线。

### 5.2 数据

- 句读数据：`llm/data/train.jsonl` + `eval.jsonl`（295 条，80-150 字短样本）。
- 真值扩展：识典古籍公开全文按章节导入，可扩展至数万条。
- 防遗忘数据：`cnbe_train.jsonl`（178,034 条）。

### 5.3 QLoRA 配置要点

| 项 | 值 |
|---|---|
| 量化 | 4-bit NF4 |
| LoRA r / alpha | 16 / 32 |
| 目标模块 | 全部线性层 |
| 最大长度 | 1024 |
| 批次 | 1-2，梯度累积 8 |
| 学习率 | 5e-5，cosine |
| Epochs | 3-5 |
| 思考模式 | 关闭（纯文本续写） |
| 混合 CNBE | 每轮 10,000 条 |

### 5.4 验证

- 句读指标：标点 P/R/F1（`scripts/eval_punctuator.py`），目标 F1 >= 0.90。
- CNBE 知识保留：在 8,105 字 CNBE 评测集上抽测，目标准确率不回退。
- 管线集成：`Yongle_LLM_Pipeline` 知识库命中后调用 14B 句读。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 14B 权重未下载 | 提供镜像下载命令与断点续传 |
| 显存不足 | 4-bit + gradient checkpointing + 更小批次 |
| CNBE 知识遗忘 | 每轮混入 10,000 条 CNBE 样本 |
| 句读过度标点 | 后处理规则过滤，控制标点密度 |

## 7. 结论

今日失败不是资源浪费，而是为 14B 训练提供了完整的问题边界、评测方法和
数据资产。按照本白皮书路线，14B 将作为“古籍句读专家”接入识典模式产线，
与 CNBE-32 形成“真值 + 句读 + 结构编码”的完整闭环。
