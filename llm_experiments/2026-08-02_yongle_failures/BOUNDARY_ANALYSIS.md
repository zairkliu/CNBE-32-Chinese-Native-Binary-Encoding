# 小模型上 LLM 与 CNBE-32 的能力边界：基于今日失败实验的真实讨论

日期：2026-08-02

## 1. 我们讨论的“小模型”是什么

本文中的“小模型”指可以在消费级设备上本地训练/推理的规模：

- 0.8B：Qwen3.5-0.8B（原 CNBE 训练基座）
- 1.5B：DeepSeek-R1-Distill-Qwen-1.5B（今日失败实验）
- 14B：DeepSeek-R1-Distill-Qwen-14B（下一步训练目标，消费级上限）

“边界”指模型在什么任务上可靠、在什么任务上必然失败，以及 CNBE-32
作为确定性编码与概率模型之间的分工边界。

## 2. 今日实测到的边界

### 2.1 LLM 的边界

| 任务 | 模型 | 结果 | 边界含义 |
|---|---:|---:|---|
| 整页 OCR 转录（400-500 字） | 1.5B v3/v4 | 约 20-21%，Eval Loss 可升到 9.9 | 超过约 300 字的长序列精确复制超出小模型能力 |
| CNBE 精确编码查询 | 1.5B（1000 步 CNBE 域适配） | 精确匹配 0% | 概率生成无法做确定性查表 |
| CNBE 编码格式 | 1.5B | 格式 98% | 模型学会了“长得像”，没学会“是对” |
| CNBE 结构字段（部首/笔画/结构） | 1.5B | 结构字段 36% | 语义字段有微弱信号，但远不能当数据库用 |
| 规则句读（无模型基线） | 规则器 | F1=0.0933 | 规则不是答案，但可作为无模型下限 |

### 2.2 CNBE 的边界

CNBE-32 是**确定性编码**，不是模型：

- 已收录汉字（8,105 字目录）：查表 100% 精确、零幻觉；
- 未收录/生僻/OCR 变体字：覆盖率为零，结构字段无法推断；
- 今日《永乐大典》整页 CNBE 覆盖：336/429（约 78.3%），说明真实古籍
  中约两成字不在当前目录；
- CNBE 提供部首、笔画、结构的结构化距离，但没有任何语义或上下文。

### 2.3 真值库的边界

- 37 页页面锚定命中 100%，这是“查表”逻辑的胜利；
- 识典公开全文与人工校订逐字一致 100%；
- 但真值库只能覆盖“已有真值的页面”，未覆盖页只能退到 OCR 兜底。

## 3. 边界的本质

### 3.1 LLM 是分布采样器，不是字典

LLM 输出的是“下一个 token 的条件概率”，哪怕训练 178K 条 CNBE 样本，
它记住的也是分布，不是字典键值。精确匹配 0% 说明：

```text
P(输出正确编码 | 输入汉字) 不会收敛到 1.0，只能接近某个 < 1 的值
```

对“必须全对”的编码任务，任何一个 < 100% 的概率都不可接受。

### 3.2 长上下文不是线性退化，是崩坏

400-500 字整页转录中，Loss 升至 9.9 不是“精度下降”，而是模型开始
乱猜与重复。小模型的位置记忆与注意力无法维持这么长的精确复制。
80-150 字短片段则处于模型舒适区。

### 3.3 CNBE 没有泛化，只有查找

CNBE 对已收录字是双射，对未收录字没有推断能力。这既是优点
（可验证、可审计、零幻觉），也是边界（覆盖率硬约束）。

## 4. 分工边界表

| 任务 | 责任层 | 失败模式 | 防护 |
|---|---|---|---|
| 字形识别 | OCR / 真值库 | 覆盖率与精确率低（18-38%） | 页面锚定命中即 100% |
| 阅读顺序 | 几何规则（分栏/排序） | 栏线误检、大字合并失败 | CNBE 行级锚点校验 |
| 精确编码查询 | CNBE 数据库（sqlite） | 未收录字 | 覆盖率计数 + 人工补录 |
| 句读与分段 | LLM（14B 目标） | 过度/不足标点 | F1 评测 + 后处理规则 |
| 校勘差异 | 规则 diff | 误报 | 人工校对队列审计 |
| 知识保留 | 训练数据混合 | 灾难性遗忘 | 混入原 CNBE 178K 样本 |

## 5. 为什么两者不能互相替代

### 5.1 LLM 不能替代 CNBE

- 生成式编码无法保证确定性；1.5B 精确匹配 0% 是硬证据；
- 即使 14B 改善，也无法在“必须全对”场景替代查表；
- CNBE 应由 SDK/数据库计算，LLM 只允许做结构加工（标点、分段）。

### 5.2 CNBE 不能替代 LLM

- CNBE 没有语义，无法断句、分段、理解文意；
- CNBE 是字级结构指纹，不是语言模型；
- 识典古籍模式也证明：准确文本来自“专用 OCR + 人工校对”，
  语义加工仍需要模型能力。

## 6. 诚实的限制

以下限制必须随文档公开，避免过度解读：

1. 样本仅 37 页、单卷《永乐大典》，统计显著性有限；
2. 句读基线是规则器，不是 14B 模型；14B 尚未训练；
3. CNBE 覆盖 78.3% 受目录（8,105 字）限制，不代表编码方案本身失败；
4. DeepSeek-OCR-2 在连续多页返回空，可能与环境/参数有关，不能据此否定该模型；
5. 识典公开文本用于交叉验证与数据导入，发布需遵守其使用条款；
6. 1.5B 结果在特定数据划分下得到，扩样后数字可能变化，但“任务错配”
   的定性结论与识典/行业实践一致。

## 7. 下一步边界实验

1. **规模曲线**：同一句读任务对比 1.5B / 7B / 14B，标点 F1 随规模的变化；
2. **长度扫描**：30/80/150/300 字输入，观察 F1 与重复率拐点；
3. **知识保留评测**：14B 训练前后在 8,105 字 CNBE 抽测集上的准确率差；
4. **未收录字检测**：CNBE 覆盖率不足时，系统应显式报警而非静默降级；
5. **误报审计**：形近字标记的人工抽检，统计真实误报率。

## 8. 结论

小模型与 CNBE 的边界不是“谁更聪明”，而是**任务性质**：

- 需要确定性的任务交给查表（真值库、CNBE 数据库）；
- 需要语义的任务交给 LLM（句读、分段）；
- 需要几何的任务交给规则（阅读顺序）；
- 需要人工判断的交给校对队列。

今日失败的价值，是把这条边界从推测变成了带数据的结论。
