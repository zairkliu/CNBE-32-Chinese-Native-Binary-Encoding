# CNBE-MoE 全链路白皮书

版本：2.0  
日期：2026-08-18  
范围：国家标准对齐 → 项目评估 → Ubuntu 26.04 + Ollama DeepSeek-R1 1.5B 针对性训练 → A800×2 双卡训练

## 摘要

本项目从 CNBE-32 与 GB 8105 等国家标准的对齐开始，先完成项目可行性评估，再在 Ubuntu 26.04 + Ollama DeepSeek-R1 1.5B 上做针对性 LLM 训练，随后进入七语料验证、MoE 原型、SCNet 多卡训练，最终启动 A800×2 5.4B 全量训练。

整条路径的核心结论是：

1. CNBE-32 是结构编码器，不是语义嵌入器；
2. 1.5B 生成式模型无法承担变体归一化等任务，需要确定性规则或更大模型；
3. MoE-128 在同数据上明显优于 Dense 和 Unicode 基线；
4. 语料冻结、哈希校验、确定性切分、逐步日志是实验可复现的基础；
5. A800×2 冒烟验证通过，正式训练已具备启动条件。

## 1. 阶段 0：国家标准对齐

### 1.1 对齐标准

CNBE-32 以 GB 8105《通用规范汉字表》为核心基线，并逐项对齐：

| 标准 | 对齐内容 |
|---|---|
| GB 8105 | 通用规范汉字核心基线 |
| GF 0011-2009 | 汉字部首表 |
| GF 0012-2009 | GB13000.1 字符集部首归部规范 |
| GF 0013-2009 | 现代常用独体字规范 |
| GF 0017-2013 | 汉字结构分类 |
| GF 0023-2020 | 通用规范汉字笔顺规范 |

### 1.2 数据状态

| 指标 | 值 |
|---|---:|
| 8105 基线行数 | 8,105 |
| 运行时总行数 | 21,178 |
| 标准轨行数 | 7,602 |
| 已授权 PENC276 编码 | 276 |
| 已标准化修复 | 598 + 620 |

每条编码重建记录需通过 13 道门禁，包括 Unicode 身份、国标证据、笔画证据、结构分类、部首偏旁、人工审核授权等。

## 2. 阶段 1：项目评估

### 2.1 评审结论

2026-08-03 的方案可行性评审给出明确结论：方向可行，但初版文档不能直接照跑。

关键问题：

- 不应让模型直接学习 32 位二进制码流；
- O(1) 路由 FLOPs 不等于端到端吞吐加速；
- 8 类 Skill 路由是未经验证的手工分桶；
- 初版代码存在数据库 schema、随机训练器、路由退化等问题；
- 8GB 显存无法训练 64-896 专家全参 MoE。

### 2.2 评估后的修正

项目重新定位：

- CNBE 作为结构化辅助特征，不作为独立 token 序列；
- 路由使用已验证的 `(radix, struct, strokes)` 频率均衡映射；
- FLOPs 与真实吞吐分开报告；
- 小规模原型先验证，再扩展到多卡训练；
- 私有训练计划与模型权重不进入公开 GitHub。

## 3. 阶段 2：Ubuntu 26.04 + Ollama DeepSeek-R1 1.5B 针对性训练

### 3.1 环境

| 项 | 值 |
|---|---|
| 系统 | Ubuntu 26.04（WSL2） |
| 推理 | Ollama + deepseek-r1:1.5b |
| 训练 | DeepSeek-R1-Distill-Qwen-1.5B QLoRA |
| GPU | RTX 4060 Ti 8GB |
| 训练时间 | 1000 步约 1 小时 32 分钟 |

### 3.2 训练结果

针对 8105 规范汉字的 CNBE 编码与解码任务：

| 指标 | 值 |
|---|---:|
| 训练样本 | 12,163 |
| 验证样本 | 1,520 |
| 测试样本 | 1,521 |
| 最终 eval loss | 0.0918 |
| 有效 hex 格式 | 47% |
| 精确匹配准确率 | 0% |

结论：模型学到了 CNBE 的格式，但没有掌握精确映射，1.5B 生成式模型在该任务上存在能力边界。

### 3.3 T1 负结果

变体归一化实验进一步确认：

| 轮次 | eval_loss | 结果 |
|---|---:|---|
| v1 | 2.309 | 生成式替换失败 |
| v2 | 2.279 | 生成式替换失败 |
| v3 | 1.988 | 保留繁体但替换失败 |
| v4 | 2.095 | 显式规则也无法执行 |

因此关闭本地 1.5B 文本生成微调线，改用确定性映射 + CNBE 重排，并保留 T1 数据与训练管线供后续复用。

## 4. 阶段 3：七语料验证

### 4.1 数据

七类语料累计 24,381,237 个中文字符，覆盖古文、现代白话、翻译小说、技术文档、武侠、杂志、古籍诗集合集。

### 4.2 关键结果

- CNBE 覆盖率 99.98%-100%；
- 16 专家 Gini 接近 0；
- CNBE 路由代理准确率 74%-84%；
- 句读 F1 在 0.48-0.85 之间波动，说明语料类型与 OCR 噪声影响显著；
- gzip 仍是纯压缩最优，CNBE 的价值在字段预测、结构检索和 O(1) 随机访问。

## 8. 错误与转变路径

### 8.1 从错误到规则

1. 日志丢失 → 强制 `tee training.log`；
2. checkpoint 覆盖 → `step_*.pt` 独立保存；
3. NCCL 尾部崩溃 → `final.pt` 先于 collective；
4. 数据版本混乱 → 冻结包 + SHA 校验；
5. zip 嵌套路径 → 只提取 `frozen/`；
6. 镜像超限 → 迁移到 private_data；
7. 19G 全量读入内存 → `StreamCodeDataset`；
8. step 曲线丢失 → 每步写 `step_metrics.jsonl`。

### 8.2 想法转变

- 从“让模型学习二进制码流”转为“CNBE 作为结构特征 + 硬路由”；
- 从“本地 1.5B 生成式微调”转为“确定性规则 + 大模型训练”；
- 从“FLOPs 理论加速”转为“真实吞吐与 Gini 共同报告”；
- 从“不可复现实验”转为“冻结、哈希、分片、逐条落盘”。

## 9. 方向分析

### 9.1 已验证

- CNBE 结构字段可被 MoE 路由使用；
- MoE-128 优于 Dense 和 Unicode；
- 冻结语料与数学恒等式可保证复现；
- 1.5B 生成式模型边界已被负结果记录。

### 9.2 未验证

- 5.4B 全量最终指标；
- 同参数 Dense matched；
- 下游任务增益；
- 多 seed 显著性；
- 多卡扩展效率。

### 9.3 建议边界

当前阶段聚焦验证 CNBE 编码方法论。A800×2 完成后，再决定 4/8 卡扩展。

## 10. 结论

本项目已形成从国家标准到结构编码、从 1.5B 负结果到 MoE 原型、从 SCNet 多卡到 A800 全量训练的完整证据链。正式训练是最后一块核心拼图。
