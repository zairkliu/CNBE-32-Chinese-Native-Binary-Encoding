# CNBE 定位分析：通用 NLU 边际增益 vs 结构敏感任务

日期：2026-08-19  
来源：外部评审观点 + 项目已有证据

## 1. 外部评审的核心论点

1. 在通用 NLU/LLM 上，显式结构先验的增益是边际的，例如 CNM-BERT 在 CLUE 上平均只 +0.19；
2. 大模型会在中上层隐式重建字结构（CharBench / Uzan 2025）；
3. 因此“结构先验大模型学不到”的说法不完全成立，大模型学得到，小模型学不全；
4. CNBE 不应定位为“重新发明中文底层编码”，而应定位为“为结构敏感任务提供可计算的结构指纹层”；
5. 该赛道已有 ChineseBERT / Glyce / UnihanLM / SubChar / CNM-BERT，需要回答差异化优势。

## 2. 我们认为评审在哪些点上成立

- 成立：大模型不一定需要显式结构先验；
- 成立：通用 NLU 的显式结构增益通常很小；
- 成立：CNBE 不是 Unicode/GB 的替代品；
- 成立：论文必须对标已有结构感知工作；
- 成立：CNBE 的真正证据集中在字符级、结构敏感任务。

## 3. 项目已有证据与定位的匹配

| 任务 | 项目证据 | 是否结构敏感 |
|---|---|---|
| 形近字消歧 | API ablation +33.3pp，CNBE hint 0.933 vs plain 0.600 | 是 |
| 结构分类 | 1.5B 模型结构分类 66% | 是 |
| OOV / 未见过字泛化 | 未见过字与已见字表现接近 | 是 |
| 路由代理 | 74%-84% 准确率 | 是 |
| 通用中文 LM 预训练 | 24M/544M/5.4B 训练 | 证据较弱，正在补强 |

结论：项目当前强证据都落在“结构敏感任务”上，而不是“通用 NLU 大幅提升”。

## 4. 与已有工作的差异化

| 方案 | 表示 | 路由 | 硬件/标准 | 主要场景 |
|---|---|---|---|---|
| ChineseBERT | Unicode embedding + glyph/pinyin features | 无 | 软件 | 通用 NLU |
| Glyce | 字符图像向量 | 无 | 软件 | 通用 NLU |
| UnihanLM | Unicode + Unihan 数据库 | 无 | 软件 | 通用中文 |
| SubChar | 字内分解 token | 无 | 软件 | 子词/序列 |
| CNM-BERT | 结构 embedding | 无 | 软件 | 通用 NLU |
| CNBE-32 | 固定 32-bit 结构字段 | 确定性映射 | 软件+硬件原型 | 结构敏感任务 |

CNBE 的差异化不是“又一个结构 embedding”，而是：

1. 固定 32-bit 字段，可直接作为 O(1) 路由键；
2. 字段与 GB 8105 / GF 系列对齐；
3. 同一表示可同时用于 SDK、数据库、MoE、RISC-V 原型；
4. 结构指纹可审计、可哈希、可复现；
5. 不需要额外编码器，输入层即携带结构信息。

## 5. 修改后的论文定位

主定位：

> CNBE 为结构敏感任务提供可计算的固定 32-bit 结构字形指纹，可作为 MoE 路由先验与字符级下游特征。

次定位：

> CNBE-MoE 在受控预训练中验证结构路由不会损害通用 next-code 建模。

不再宣称：

> CNBE 替代 Unicode/GB，或显著提升通用 NLU。

## 6. 需要新增的实验

1. OOV / 生僻字 benchmark，对比 ChineseBERT / Glyce / SubChar；
2. 形近字消歧基准，复用 +33.3pp API 消融；
3. 古籍 OCR 后处理 benchmark；
4. 手写零样本识别候选重排；
5. CLUE 子集 sanity check：证明 CNBE 不显著劣化通用 NLU；
6. 等参 Dense matched，继续回答 MoE 因果归因。

## 7. 一句话结论

评审的结论是对的：CNBE 的价值在“可计算结构指纹层”，不在“通用编码替代”。论文按这个定位写，才不会被 CCF-A reviewer 第一眼否决。
