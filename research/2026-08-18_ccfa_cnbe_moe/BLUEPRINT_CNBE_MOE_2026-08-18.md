# CNBE-MoE 蓝皮书

版本：1.0  
日期：2026-08-18  
定位：从“编码想法”到“可验证中文 AI 基础设施”的长期路线图

## 1. 愿景

让中文模型不仅知道“这是哪个字”，还知道“这个字长什么样、由什么构成”。CNBE-MoE 的目标是把国家标准汉字结构、可复现语料、MoE 训练和下游应用串成一条完整技术栈。

## 2. 原则

1. 国家标准优先：编码必须以 GB 8105 和 GF 系列标准为证据；
2. 确定性优先：能用映射表和哈希校验解决的问题，不让模型猜测；
3. 诚实评估：负结果必须封存，FLOPs 与吞吐必须分开；
4. 可复现优先：冻结数据、固定 seed、逐步日志；
5. 私有边界：训练数据与权重不进入公开 GitHub；
6. 算力纪律：先小规模验证，再扩展 GPU。

## 3. 分层架构

```text
国家标准层
  GB 8105 / GF 0011 / GF 0012 / GF 0013 / GF 0017 / GF 0023
        |
CNBE 编码层
  radix / strokes / struct / idx / extension
        |
语料冻结层
  七语料 -> V1 -> V2 frozen -> manifest + hash
        |
模型训练层
  QLoRA 1.5B -> CNBE-MoE 64 -> CNBE-MoE 128 -> A800×2 5.4B
        |
评估验证层
  next-code / field accuracy / Gini / F1 / downstream benchmark
        |
应用与发布层
  古籍整理 / OCR 后处理 / API / GGUF / Ollama
```

## 6. 治理

### 6.1 数据治理

- 私有出版物与公开法规分轨管理；
- 每个 `.cnbe` 文件必须有 manifest 和哈希；
- 数据、脚本、配置统一来自冻结包；
- 禁止在训练目录临时拼路径。

### 6.2 实验治理

- 每条指标记录 checkpoint 路径与 `tokens_evaluated`；
- 负结果单独封存；
- 变更脚本后记录 SHA256；
- 指标入库前必须通过 `verify_frozen.py`。

### 6.3 发布治理

- 公开：论文、去敏数据、评估协议、配置、脚本；
- 私有：训练权重、完整语料、内部日志、适配器；
- 不公开：未授权出版物数据。

## 7. 风险

| 风险 | 缓解 |
|---|---|
| 5.4B 训练结果不达预期 | 已有 544M/受控对比作为前置证据，结果仍可写论文 |
| 训练崩溃 | 独立 checkpoint、resume、先保存 final |
| 数据版权 | 分轨治理与去敏发布 |
| 过度扩展 | 设置算力纪律，按决策门推进 |
| 论文可复现性 | 冻结资产 + SHA + 确定性切分 |

## 8. 一页总结

CNBE-MoE 从国家标准开始，用确定性编码和冻结语料解决“可复现”，用 MoE 路由解决“结构信息进入模型”，用 1.5B 负结果解决“模型能力边界”，最终用 A800×2 完成规模化验证。项目当前只差正式训练结果。
