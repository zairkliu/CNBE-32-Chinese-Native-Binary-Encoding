# CNBE 已有工作、他人未尝试原因与差异化分析

日期：2026-08-19  
用途：回答“这些方面已经有哪些工作、为什么别人不尝试、与 ChineseBERT/Glyce/SubChar 的对比、我们项目尝试方向是否成立”

## 1. 这些方向已经有哪些工作

### 1.1 通用中文结构感知

| 工作 | 方法 | 局限 |
|---|---|---|
| ChineseBERT | Unicode token + 字形图像 + 拼音 embedding | 仍是外部特征注入，不是固定编码 |
| Glyce | 字符图像作为 glyph 向量 | 图像表示开销高，无字段代数 |
| UnihanLM | 用 Unihan 数据库做粗到细预训练 | 依赖外部知识库，非二进制字段 |
| CNM-BERT | 结构 embedding 注入 BERT | 通用 NLU 增益约 +0.19，边际 |
| SubChar | 字内分解为 radical/stroke token | 序列化分解，无固定 32-bit 字段，无硬路由 |

### 1.2 字符结构数据层

- Unicode IDS：用文本符号描述结构，CPU 不直接计算；
- CHISE：大型汉字结构数据库，主要用于查询；
- 仓颉/五笔：输入法映射，面向人机交互；
- cjkvi-ids、Unihan：结构/语义信息外部数据库；
- 四角号码、笔画输入：编码方法，不进入 token 或指令层。

### 1.3 底层编码/硬件层

现有仓库比较文档的结论是：

> CNBE-32 是目前已知唯一把汉字结构接入 CPU 指令集、OS 内核、二进制编码层、SDK、数据库、MoE 路由和古籍应用的完整尝试。

类似项目如 FuXi-128 只是把汉字用作指令助记符，不是可计算结构字段。

## 2. 为什么别人不这样做

### 2.1 生态锁定

Unicode/UTF-8/GB 已经深度嵌入操作系统、编译器、网络协议、数据库和 AI 框架。重新设计底层编码的切换成本极高，绝大多数研究者会选择“兼容现有编码 + 外加特征”，而不是建立新编码层。

### 2.2 缺少字段标准

即使有人想做结构编码，也需要对部首、笔画、结构、索引、扩展位做出可审计的字段语义定义。这个工作需要国家标准对齐、人工审核、数据治理和跨语言一致性，成本远高于训练一个 embedding。

### 2.3 ML 社区偏好学习式表示

现代 NLP 的主流假设是“让模型自己学”，显式人工特征在通用任务上往往收益边际。CNM-BERT 在 CLUE 只提升 +0.19，进一步强化了“显式结构不值得做”的印象。

### 2.4 大模型能隐式重建结构

已有证据表明大模型在中间/上层可以隐式学到字形结构。因此对“通用大模型”来说，显式结构编码不是刚需；只有小模型、OOV、OCR、古籍等结构敏感场景才更需要先验。

### 2.5 缺少结构敏感 benchmark

主流 benchmark 是 CLUE、GLUE、SuperGLUE 等通用 NLU 任务，形近字纠错、OCR 候选重排、生僻字预测不是顶会主赛道。结构编码的收益在这些 niche 任务上，通常不会被通用 benchmark 看到。

### 2.6 MoE 社区习惯 learned router

MoE 主流是 softmax gating / learned router。确定性硬路由被认为太“人工”，缺少自适应能力。但代价是路由不稳定、Gini 难控制、专家语义不透明。

### 2.7 全栈工程门槛

只做编码或只做模型，都不需要同时维护 SDK、数据库、RISC-V、Verilog、Linux、MoE、语料治理。全栈实现成本高，单领域团队通常不会投入。

## 3. 与 ChineseBERT / Glyce / SubChar 的对比

| 维度 | ChineseBERT | Glyce | SubChar | CNBE-32 |
|---|---|---|---|---|
| 输入 | Unicode + glyph/pinyin | 字形图像 | 字内 token | 固定 32-bit 字段 |
| 结构来源 | 外部特征编码器 | 图像 CNN | 分解序列 | 字段代数 |
| 是否二进制编码 | 否 | 否 | 否 | 是 |
| 确定性路由键 | 无 | 无 | 无 | 有 |
| 国家标准对齐 | 无 | 无 | 无 | GB 8105 / GF 系列 |
| 硬件原型 | 无 | 无 | 无 | RISC-V / Verilog / Linux |
| O(1) 查询 | 无 | 无 | 无 | 有 |
| 主要场景 | 通用 NLU | 通用 NLU | 子词建模 | 结构敏感任务 |
| 零样本结构距离 | 弱 | 弱 | 弱 | 可直接计算 |

核心差异化：

1. ChineseBERT/Glyce/SubChar 都是“给模型额外特征”，CNBE 是“把结构做成 token 自身可计算的字段”；
2. 它们没有确定性路由接口，CNBE 可以直接映射 `(radix, struct, strokes) -> expert`；
3. 它们没有硬件/系统层，CNBE 有同一字段语义贯穿 SDK、数据库、指令和内核原型；
4. 它们不承诺国家标准审计，CNBE 有 21,178 行数据库和 13 道编码重建门禁。

## 4. 我们项目尝试方向的分析

### 4.1 方向是否成立

成立，但必须收敛定位。

成立的部分：

- 结构敏感任务已经有真实收益：形近字消歧 +33.3pp，零样本候选重排优于 Unicode；
- 确定性硬路由解决了 learned router 的 Gini 不透明问题；
- 全栈一致性提供了“一个结构表示、多种用途”的独特价值。

不成立/需要谨慎的部分：

- 如果宣称“CNBE 替代 Unicode/GB”或“显著提升通用 NLU”，证据不足；
- 如果只和 Unicode+Dense 对比，不对比 ChineseBERT/Glyce/SubChar，会被 reviewer 视为旧 baseline；
- 大模型隐式重建结构后，显式先验的增量会缩小；
- 32-bit 字段存在碰撞/lossy 风险，需要持续审计。

### 4.2 我们的论文定位

> CNBE 是一个面向结构敏感任务的、国家标准对齐的、可计算固定 32-bit 结构指纹层，并可作为 MoE 确定性路由先验。

不是：

> 重新发明中文底层编码。

### 4.3 已完成的实验证据

2026-08-19 完成零样本候选重排实验：

| 方法 | Top-1 | MRR |
|---|---:|---:|
| Random | 2.88% | 0.1599 |
| Unicode 码点距离 | 46.15% | 0.5928 |
| CNBE field-weighted | 48.08% | 0.6070 |
| CNBE bit Hamming | 50.96% | 0.6402 |

这证明 CNBE 不需要训练即可提供结构敏感的候选排序。

## 5. 结论

这些方向不是没有人想过，而是此前被生态、成本、字段标准和通用 benchmark 挡住了。CNBE 的差异化在于“固定字段 + 国家标准 + 确定性路由 + 全栈一致性”，而不是“又一个结构 embedding”。

论文应投结构敏感任务应用方向，并补足与 ChineseBERT/Glyce/SubChar 的对比。只有等参 Dense、真实 OCR 对、通用 NLU sanity 三项补齐后，才能形成完整的 CCF-A 证据链。
