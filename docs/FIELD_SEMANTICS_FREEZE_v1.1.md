- 状态：**草案，待治理流程批准**（gate 12，需人类授权后方可改动任何源表）
- 工作流：PDR WS-3；输入：WS-2 交叉验证队列（PR #41）+ Issue #39 四项缺陷
- 证据可复现：本文件所有数字由 `scripts/freeze_evidence.py` 对 `data/cnbe32.db`
  （v1.0.4 运行时库，20,902 行）实地跑出，命令见附录 A

  治理批准的迁移工作流

## §0 WS-3 新实证发现（超出 Issue #39 的部分）

| # | 发现 | 影响 |
|---|---|---|
| N1 | `struct_type` 同一列存在**两套编号**：中文轨 13 值（0=独体字…12=镶嵌）与英文轨 12 值（0=single…11=full-wrap，顺序不同：英文轨 1=左右而中文轨 1=上下） | 不指明轨道，`struct_type` 无法解释 |
| N2 | `idx` 精确满足 `idx = (unicode - 0x4E00) mod 2048`（20,902/20,902 行，0 例外）——11-bit 环绕偏移，均值每个 idx 10.21 行、最多 11 行 | idx 是**有损哈希**，不能作寻址键 |
| N3 | 8105 范围内 7,829 行的轨道构成：中文轨 7,310 / 英文轨 482 / triangle 37 | 标准轨覆盖率 93.4% |
| N4 | 中文轨行质量（8105 内）：结构 vs IDS 一致 **97.9%**（实质分歧仅 3 行）、部首 vs 康熙 96.7%；英文/triangle 轨：部首一致 **0.6%**、结构实质分歧 402/482 | 两轨道不是"质量差异"，是"可用与不可用"的差异 |

## §1 F1 — `struct_name` 冻结

**现状实证**：26 种取值 = 13 个治理批准中文标签（7,310 行）+ 12 个英文遗产标签
（12,529 行）+ 未批准 `triangle`（1,063 行）。

**冻结决策**：
1. v1.1 起，`struct_name` 合法取值**仅为 13 个规范中文标签**，与 GF 0017-2013
   §3.12 一一对应：独体字、上下、上中下、左右、左中右、左上包、右上包、左三包、
   左下包、上三包、下三包、全包围、镶嵌。
2. 12 个英文标签为遗产轨标记，**不做 1:1 改名迁移**——英文轨行整体质量不可用
   （N4），改名会把垃圾数据洗成"规范外观"。英文轨行进入重标工作流，不按行保留。
3. `triangle`（1,063 行）处理：
   - 证据：全部 1,063 行 `struct_type=12`（中文轨编号→镶嵌），但抽样即见反例
     （侒 U+4F92 为明显左右结构却被标 triangle），该标签语义本身不在 13 类中。
   - 决策：8105 内 37 行→ 走 WS-2 队列 P1 专家裁决；8105 外 1,026 行→
     随英文轨一并重标。**禁止**批量改名 triangle→镶嵌。

**迁移规则**：`struct_name ∈ 13 规范标签`成为入库校验（gate 校验项）；遗产行在
重标完成前保留原值并打 `track=legacy` 标记（见 §6）。

**验证**：`freeze_evidence.py` E1 段 + 治理抽检。

## §2 F2 — `struct_type` 双编号冻结（本规范最重要的新发现）

**现状实证**（N1）：

| struct_type | 中文轨含义（行数） | 英文轨含义（行数） |
|---|---|---|
| 0 | 独体字 (246) | 独体字 single (1,036) |
| 1 | 上下 (1,616) | **左右** left-right (1,035) |
| 2 | 上中下 (55) | **左中右** left-mid-right (1,062) |
| 3 | 左右 (4,740) | **上下** up-down (1,037) |
| 4 | 左中右 (23) | 上中下 (1,031) |
| 5 | 左上包 (276) | 左上包 (1,050) |
| 6 | 右上包 (52) | 右上包 (1,060) |
| 7 | 左三包 (15) | **左下包** bottom-left-wrap (1,053) |
| 8 | 左下包 (165) | **上三包** top-wrap (1,038) |
| 9 | 上三包 (66) | **下三包** bottom-wrap (1,049) |
| 10 | 下三包 (6) | **左三包** left-wrap (1,037) |
| 11 | 全包围 (27) | 全包围 (1,041) |
| 12 | 镶嵌 (23) | —（英文轨无 12；triangle 行挂在 12） |

各轨内部 `struct_type↔struct_name` 均完全一致，即**列内无随机噪声，噪声是系统性的
双编号**。

**冻结决策**：
1. v1.1 冻结 `struct_type` 编号为**中文轨 13 值**（0=独体字，1=上下，2=上中下，
   3=左右，4=左中右，5=左上包，6=右上包，7=左三包，8=左下包，9=上三包，
   10=下三包，11=全包围，12=镶嵌），与 GF 0017-2013 顺序对应。
2. 英文轨编号（0–11）**整体废弃**，不做数值重映射（英文轨行重标后按冻结编号写入）。
3. 在编号冻结前，任何代码**禁止**脱离轨道标记单独消费 `struct_type`。

**验证**：`freeze_evidence.py` E2/E3 段；迁移后校验 `struct_type` 与 `struct_name`
全局一致（目标：不一致行数 = 0）。

## §3 F3 — `strokes` 语义与溢出规则

**现状实证**：范围 1–31；8105 内与 Unihan `kTotalStrokes` 一致 93.5%（511 行分歧）；
遗产轨一致仅 3.2%（12,650/13,073 错）；`strokes=31` 的 431 行中 430 行为错值（N5）。

**冻结决策**：
1. 字段语义冻结为：**按 GF 0013-2009 规范的真实笔画数**（整数，无上限语义）。
2. 数据层**如实存真值**，包括 >31 的字（如 龘 48 画）；物理编码层（5-bit 字段）的
   溢出表示是**编码协议问题**，归 WS-6 硬件/编码协议处理，数据层不做截断。
3. 错值修复来源优先级：**GF 0013（标准）> Unihan kTotalStrokes（交叉参考）**；
   8105 内 511 行分歧与 430 行 `=31` 错值进入裁决队列，标准文本到手前不许批量改。

**待裁决**：笔画真值的权威机器可读来源（GF 0013 逐字笔画）——北语合作输入项。

## §4 F4 — `radix` 锚定 GF 0011-2009

**现状实证**：取值 1–214（康熙 214 部首体系），无空值、无越界；8105 内中文轨与
Unihan `kRSUnicode`（康熙口径）一致 96.7%。

**冻结决策**：
1. v1.1 起，`radix` 语义锚定 **GF 0011-2009 的 201 主部首**；附形部首按 GF 0011
   归并规则入主部首。
2. 迁移 = 映射表 `康熙214 → GF 0011 201`；映射表本身是**标准内容**，必须来自权威
   来源并在治理文档登记版本，**禁止**由模型生成后直接使用。
3. 当前康熙口径 96.7% 一致率仅作为质量基线存档，**不构成** GF 0011 合规证据
   （两体系部首数不同、归部规则有差异）。
4. GF 0011 之外的字（遗产轨、扩展区）暂保留康熙口径并打 `radix_scheme=kangxi`
   标记，待扩展方案。

**待裁决**：GF 0011 映射表的权威机器可读来源 —— 北语合作输入项；WS-2 队列 P2 中
754 行部首分歧须在映射表冻结后按新口径重审。

## §5 F5 — `idx` 寻址协议

**现状实证**（N2）：`idx = (unicode - 0x4E00) mod 2048`，11-bit 环绕，
平均每个取值 10.21 行——Issue #39"idx 耗尽 2047"的完整解释：不是将要耗尽，
是**从来就不是唯一键**。

**冻结决策**：
1. **废弃 `idx` 作为寻址/索引字段**；唯一标识符为 Unicode 码位（`unicode` 列）。
2. 兼容过渡：若下游确需块内偏移，定义为 `block_offset = unicode - 0x4E00`
   （CJK 统一表意文字块内 15-bit 偏移，块内唯一），新列新增而非改 `idx` 语义。
3. `idx` 列在 v1.1 标记 **deprecated**，仅保留只读兼容，v1.2 移除。
4. 任何"用 idx 当数组下标/哈希键"的下游用法视为缺陷，迁移期登记在案。

**验证**：`freeze_evidence.py` E4 段（公式 0 例外即为本决策的实证基础）。

## §6 迁移与版本策略（v1.0.x → v1.1）

1. 本规范合入后，数据层变更集中为**一次治理批准的迁移**，对应发版 v1.1.0；
   迁移前所有修复项只进队列，不进源表。
2. 迁移内容（以治理批准为准）：英文轨重标、triangle 裁决、`strokes=31` 错值修复、
   `radix` 换锚 GF 0011、`idx` 弃用 + `block_offset` 新增、`track` 标记列新增。
3. 迁移后入库校验（新 gate）：`struct_name ∈ 13 标签`、`struct_type` 冻结编号一致、
   `strokes ≥ 1` 整数、`radix` 在 GF 0011 体系内或带 `kangxi` 标记。
