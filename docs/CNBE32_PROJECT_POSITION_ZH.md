# CNBE-32 项目定位重定义

日期：2026-08-04

## 定位陈述

CNBE-32 不是依附于 CJK 的编码格式，而是一项**面向中文的完整原生编码体系**，
目标是在机器码、指令集、操作系统、编译/解码器、编程语言与应用之间建立统一的、
可计算的中文结构表示。

技术上，它以 32 位字段代数（radix / stroke / struct / index / ext）承载可计算的
形态学信息，形式化定义了字段提取、加权形态汉明距离与二进制向量空间，并提供
RISC-V 自定义指令、Verilog 原型与 Linux 内核层实验作为硬件与系统纵深；
与 Unicode/GB 的兼容仅是面向现有计算机与网络协议的最大公约数互操作层。

共时性上，它把现代规范汉字（8105 基线）与 GB 18030 / Unicode 的扩展字符集
作为同步系统整体对齐；历时性上，它服务于《永乐大典》《资治通鉴》等古籍的
OCR 修正、形近字消歧与句读，构成数字人文的中文计算基础。

学术上，它把“编码即结构”形式化为可验证的数学规范（形态距离、双曲嵌入、
golden vectors），并已在字符结构分类、形近字区分、OCR 后处理、MoE 结构路由
与跨领域 32 位字段实验中取得可复现证据，为计算语言学、汉字学与数字人文
提供新的编码基座。

## 共时性与系统性

- 同步系统：8105 规范汉字、GB 18030 / Unicode 扩展字符集作为整体对齐对象；
- 可计算形态：编码距离与汉字形态相似性建立可计算关联；
- 全栈一致：同一字段语义贯穿寄存器、指令、内核、编译/解码器与应用层。

## 文学与学术价值

- 数字人文：为《永乐大典》《资治通鉴》等古籍提供 OCR 修正、形近字消歧、
  句读与版本比对的统一计算表示；
- 汉字学：部首归部、结构分类、笔画与构形证据可编码、可审计、可复现；
- 计算语言学：结构感知编码为小模型提供可学习的形态特征；
- 形式化基座：形态距离、双曲嵌入与 golden vectors 构成可验证的学术规范。

## 时代条件：为什么以前不行，现在可以

- 20 世纪 80 年代，老一辈科学家曾提出“全中文计算系统”的设想；
  当时受限于硬件算力、存储规模、软件生态，以及 Unicode/GB 等国际标准的
  主导地位，该设想缺乏工程落地条件；
- 如今，人工智能与 Agent 的发展、芯片与存储的几何级增长，使实时转码、
  代码迁移、AI 实时翻译、金融实时分析等能力从设想变为普遍现实；
- 中国已成为人工智能的两大引领国家之一；芯片全国产化、RISC-V 在国内的发展、
  自有架构与开源 AI 系统，为“中文原生计算”提供了前所未有的基础；
- CNBE-32 正是在这一时代条件下，把“全中文计算系统”从历史设想转化为
  可讨论、可验证、可工程化的技术选项。

## 中文的三次缺席与范式窗口

1. **第一次缺席（18-19 世纪）**：现代学科划分与知识分类体系以拉丁语系为框架
   构建，中文缺席了权威名词核定与知识体系奠基的历史进程；
2. **第二次缺席（1940-1970 年代）**：计算机底层架构定型期，二进制逻辑、
   ASCII、操作系统内核与编程语言全部基于英文字母线性组合逻辑，
   汉字因“无法编码”被排除在底层架构之外；
3. **第三次缺席（2022 年至今，正在发生）**：AI 底层架构定型期，
   Transformer 与 tokenization 正在固化；中文语料全球占比仅约 1.3%，
   汉字结构信息在 token 层被彻底打散；
4. **芯片镜鉴**：范式转换期是后发者实现跨越的历史窗口；
5. **项目判断**：AI 时代是中文计算的新范式窗口。**中文不应再是“选项”，
   而应成为计算与人工智能的地基之一**；CNBE-32 以结构编码作为地基层，
   提供中文原生、可计算、可硬件对齐的底座。

## 与 CJK/Unicode 的关系

- 兼容 = 最大公约数互操作层；
- 兼容 ≠ 依赖：CNBE 拥有独立的位域语义、结构字段、路由协议与硬件对齐目标；
- 长期目标：中文原生独立表示，Unicode 仅作为对外互操作接口。
