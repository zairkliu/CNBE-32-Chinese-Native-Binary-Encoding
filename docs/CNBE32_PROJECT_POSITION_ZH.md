# CNBE-32 项目定位重定义

日期：2026-08-04

## 定位陈述

CNBE-32 是一项**面向中文的完整原生编码体系**，目标是在机器码、指令集、
操作系统、编译/解码器、编程语言与应用之间，建立统一的、**可计算的中文结构表示**。

作为研究项目，32 位不是目标，而是当前最能模拟中文结构编码的载体：
它以 32 位字段代数承载部首/笔画/结构/索引/扩展位，形式化定义形态距离与
二进制向量空间，并贯通 RISC-V 指令、Verilog 原型、Linux 内核层、
编译/解码器与应用层。

实验同时暴露了明确的技术边界：

- 32 位编码偏短，无法覆盖古籍用字与汉字发展历史的完整规模；
- 定位编码的“不变压缩”能力作为结构附件仍需进一步优化；
- 这些边界将作为后续位宽扩展与编码治理的输入，而不是被回避。

## 兼容现有编码，而非另起炉灶

CNBE-32 兼容现有 CJK/Unicode/GB 编码，而不是完全另起炉灶，原因如下：

1. **历史教训**：早期激进编码因完全不兼容，既限制自身发展，又要求整个
   系统重构；CNBE 选择兼容路径，避免重蹈覆辙；
2. **工程现实**：现有计算机结构以 Unicode/GB 为基础。兼容可以通过补丁和
   更新实现，让现有系统先理解结构内的兼容编码，以更小的算力完成转码；
   网络传输也只需微调即可使用；
3. **渐进路径**：先让这套逻辑在兼容层上逐步成为规范，使中文真正“入住”
   计算机系统成为可能；同时避免项目初期因过度激进而遭遇巨大阻力
   与发展限制。

## 共时性与系统性

- 同步系统：8105 规范汉字、GB 18030 / Unicode 扩展字符集作为整体对齐对象；
- 可计算形态：编码距离与汉字形态相似性建立可计算关联；
- 全栈一致：同一字段语义贯穿寄存器、指令、内核、编译/解码器与应用层。

## 文学与学术价值

- 数字人文：为《永乐大典》《资治通鉴》等古籍提供 OCR 修正、形近字消歧、
  句读与版本比对的统一计算表示；
- 汉字学：部首归部、结构分类、笔画与构形证据可编码、可审计、可复现；
- 计算语言学：结构感知编码为小模型提供可学习的形态特征；
- 形式化基座：形态距离、双曲嵌入与 golden vectors 构成可验证的学术规范。

## 时代条件与三次缺席

- 新技术建立在现有逻辑之上：计算机信息系统是沿用和缝补了 40 多年的系统逻辑，
  CNBE 的演进路径必须尊重这一现实；
- 80 年代“全中文计算系统”设想受限于算力与生态未落地；如今 AI/Agent、
  国产芯片、RISC-V 与开源 AI 系统使其重新具备工程化基础；
- 中文经历三次缺席（学科体系奠基期、计算机底层架构定型期、AI token
  架构定型期）；AI 时代中文不应再是“选项”，而应成为计算与人工智能的
  地基之一。
