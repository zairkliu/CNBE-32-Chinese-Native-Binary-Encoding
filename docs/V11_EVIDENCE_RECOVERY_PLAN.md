# v11 实验运行证据恢复计划

**状态：执行中；性能发布门禁关闭**  
**对应清单：** `llm_experiments/v11_8105_qlora/RUN_MANIFEST_v0.json`

## 目标

将历史上混杂的训练、评测和模型制品记录拆分为可识别实验谱系。目标不是追认既有性能数字，而是建立下一次可复现实验所需的最小证据链。

## 已确认事实

1. 仓库含有 Qwen 0.8B 的 5,000 步训练脚本与日志，数据选择方式为从 178,034 行输入中经 seed=42 打乱后取前 25,000 行。
2. 仓库的 DeepSeek-R1-Distill-Qwen-1.5B 训练报告记录为 1,000 步完成。
3. ModelScope 只可直接核验 GGUF 文件身份，尚不能从已提交材料证明其来自上述任一训练谱系。
4. 50 字字段评测中，44 个响应格式有效，但只有 9 个不同的预测十六进制值，且全字段精确率为 0%。因此不能把格式有效、单字段命中或不同输出率解释为正确编码能力。
5. 41 对形近字的“不同输出”只表示输出不同，不等于两字均被正确编码。
6. 古籍距离统计不包含 OCR 正确率或字段正确率，不能构成端到端 OCR 成功结论。

## 禁止发布的表述

在清单进入 `verified` 前，禁止在 README、白皮书、ModelScope 模型卡、发布说明或演示中将下列内容表述为已确认性能结论：

- 5,000 步训练、5.8 小时训练时长或特定 loss；
- 66.0% 结构分类、92.7% 形近字区分、54.0% 笔画容忍结果；
- “生僻字泛化已证实”“编码知识不是记忆”“古籍 OCR 已验证”等结论；
- GGUF 与某一 LoRA/训练运行已等价的结论。

## 恢复步骤

### R1：建立不可变输入

- 固定基础模型名称、revision、许可证和下载哈希。
- 固定训练数据快照、生成脚本、输入 SHA-256 和许可说明。
- 固定训练、验证、测试字符集合，保存 Unicode 码点列表与 seed。
- 禁止同一字符或同一编码记录跨集合泄漏。

### R2：建立可识别训练运行

- 每次运行生成 `run.json`：命令、环境、GPU、库版本、seed、超参数、起止时间。
- 保存 adapter 与 checkpoint 哈希；转换 GGUF 后保存转换命令和 GGUF SHA-256。
- 将 ModelScope revision 与 GitHub run manifest 相互引用。

### R3：重做评测

- 以完整字段精确率为主指标；格式有效率、单字段命中与容忍误差只能作为辅助指标。
- 对形近字任务报告“两个字符均字段正确且可区分”的比例，而不是仅报告不同输出。
- OCR 任务分别测 OCR 字符错误率、候选 CNBE 格式率、字段正确率和人工审核通过率。
- 至少对“数据库/规则查询”“未微调基础模型”“当前微调模型”进行同一测试集比较。
- 输出原始 JSON、聚合表、评测命令和置信区间。

### R4：复核与发布

- 用 `scripts/validate_v11_run_manifest.py` 校验清单。
- 由人类审核训练谱系、指标文字与模型卡。
- 只有清单状态变为 `verified` 后，才允许将具体性能数字重新写入公开页面。
