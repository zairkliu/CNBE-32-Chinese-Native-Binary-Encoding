# CNBE 研究计划与实验阶梯

日期：2026-08-19
状态：研究设计文件；用于约束后续实验、README、论文和演示中的主张。

## 使用说明

本文件把项目起源论文《语言主权与数字治理：中文原生 AI 治理体系的构建路径》的
相关问题意识转化为仓库可执行的方法：中文表示、数据和输出应当可追溯、可复核且
兼容现有生态。它**不**把该文关于语言治理、公共知识库或制度设计的论断当作 CNBE
的实验结论，也不公开或替代该未发表论文全文。CNBE 在这里仅检验其中一个技术子问题：
可审计的汉字结构描述是否能在明确任务中产生可测增量价值。

## 1. 长期问题

CNBE 研究的不是“是否应以新编码替换 Unicode”，而是一个兼容性问题：

> 是否能把可追溯的汉字结构信息表示为计算系统可消费的数据层，并在结构敏感任务中
> 证明其具有可复现、可解释且值得付出的增量价值？

Unicode/GB 继续承担字符身份、交换与生态兼容；CNBE 只提出结构指纹与计算特征层的
候选实现。该区分是所有实验和对外叙事的前提。

## 2. 形式对象与方法边界

对字符 \(c\)，Unicode 码点 \(u(c)\) 是身份与互操作键。CNBE 记录的是版本化的
派生特征 \(\phi(c)=(r,s,t,i,e)\)，并以当前载体编码为：

```text
E(c) = (r << 24) | (s << 19) | (t << 15) | (i << 4) | e
```

因此，研究对象是 \((u(c), \phi(c), E(c))\) 的可追溯映射，而不是另造字符集。
字段必须带数据版本、来源级别、人工审核状态和不确定性状态；任何字段的数学可逆性
都不能替代其文字学或规范性证据。现行字段限制以
[Field Semantics Freeze v1.1](./FIELD_SEMANTICS_FREEZE_v1.1.md) 为准。

## 3. 五层研究架构

| 层级 | 要回答的问题 | 主要产物 | 不可替代的验收 |
|---|---|---|---|
| R0 表示 | 一个 CNBE 值是什么意思？ | 字段规范、Unicode 映射、golden vectors | 跨语言编码/解码一致性与版本化语义 |
| R1 证据 | 结构数据为何可信？ | 来源链、8105/GF 对齐、人工审核、置信状态 | 每条数据能追溯来源或被标为不确定 |
| R2 应用 | 结构特征在哪些任务有用？ | OCR/异体字/形近字/罕见字 benchmark | 冻结数据、真实输入、独立测试集 |
| R3 模型 | 结构特征是否带来增益？ | 对照训练、消融、误差分析 | 相同口径、强基线、多种子或置信区间 |
| R4 系统 | 表示能否跨软件与硬件复用？ | SDK、数据库、指令/硬件原型 | 复现脚本与明确的性能/兼容性边界 |

上层结果不能替代下层验收。例如，模型在一项任务得分较高，不能证明字表就是国家标准；
硬件原型能运行，也不能证明模型或应用有收益。

## 4. 实验方式

### 4.1 先定义可证伪命题

每个实验必须在运行前写清楚：

- 任务、输入与输出；
- 目标人群或文本范围；
- 主指标与次指标；
- 基线及其资源预算；
- 数据切分单位；
- 何种结果会否定当前假设；
- 允许的结论与禁止的结论。

实验报告不得以“结果较高”代替问题定义。

### 4.2 OCR 与古籍任务协议

1. 候选必须来自固定版本 OCR 引擎的实际 top-N 输出，不能由真值、同页真值字符或人工
   字表回填构造。
2. 真值只用于评估；训练、验证和测试按卷、书或来源切分，避免相邻页面泄漏。
3. 发布数据清单、文件哈希、OCR 配置、候选、真值许可状态与错误分类。
4. 同时报 Top-1、MRR、覆盖率、按错误类型分层指标和 bootstrap 置信区间。
5. 结构字段、Unihan 规则、上下文模型和人工规则必须分别消融。

### 4.3 模型任务协议

1. Unicode、CNBE、Dense、MoE 与既有方法使用同一数据切分、词表策略、损失口径和
   token/算力预算。
2. `code 0`、非汉字和缺失映射必须单独建模或同时报告含/不含该类的指标。
3. 至少提供一项强 token-only 基线，以及一项结构感知基线；embedding 单点排序不能
   替代下游任务对照。
4. 报告随机种子、配置哈希、训练/评估日志与失败运行；在预算允许时提供多种子结果。
5. 训练 loss 与 eval loss、不同语料或不同类别空间的准确率不得直接横比。

### 4.4 系统与硬件协议

1. 每个原型先证明字段语义与 SDK 一致，再报告吞吐、延迟、存储或功耗代理指标。
2. 性能结论必须给出比较对象、硬件、编译参数、输入规模与测量次数。
3. RISC-V/Verilog/Linux 原型属于可移植性探索；除非有真实基准，不宣称产业性能优势。

## 5. 当前阶段的优先级

| 优先级 | 工作 | 完成标志 |
|---:|---|---|
| P0 | 合并证据边界与公开更正 | README、论文草稿、公开帖不再相互矛盾 |
| P1 | 真实 OCR top-N benchmark | 冻结候选、按卷切分、独立测试与完整错误分析 |
| P1 | Unicode baseline 与条件指标重跑 | 统一口径的复算日志、non-zero 条件结果 |
| P2 | 强基线直接对照 | 至少一项 token-only 与一项结构感知方法在同一任务上完成 |
| P2 | A800 最终评估 | 最终 eval、配置哈希、检查点/摘要与失败记录 |
| P3 | MoE 路由与系统扩展 | 在 R2/R3 通过后，以明确指标开展 |

在 P1 未完成前，不以增加专家数、扩大语料或扩大硬件叙事替代基准完整性。

## 6. 对外叙事规则

可以说：

- CNBE 是一项从汉字结构进入计算系统的长期研究计划；
- 仓库已包含可复现的表示层、数据治理产物和多个探索性原型；
- 项目正在用结构敏感任务检验其有效边界。

不能说：

- CNBE 已替代或将必然替代 Unicode/GB；
- 单一 pilot 已证明通用模型或 OCR 的稳定优势；
- 系统原型已经证明产业级硬件收益；
- 标准对齐流程等同于获得国家标准批准。

## 7. 研究成功的分级

最小成功不是“建设完整中文计算体系”，而是得到一项可被复现、可被反驳也可被引用的
结论，例如：在预先固定的结构敏感 OCR benchmark 上，某种 CNBE 特征组合相对明确基线
产生稳定增益，并能解释它改善和不能改善哪些错误。

在此基础上，结构数据库、SDK、模型路由和系统原型可以逐步形成可复用研究基础设施。
长期目标因此不靠一次承诺成立，而靠一系列独立、严谨且彼此兼容的证据逐步成立。
