# CNBE-MoE 硬路由 API 验证 —— 计划评审与消融实验结果

日期：2026-08-03
API：DeepSeek V4 Flash（`deepseek-v4-flash`）

## 一、计划评审结论

方向总体符合项目定位，但原计划存在两个需要修正的问题：

1. **“Prompt 里写 CNBE 字段”不是硬路由迁移验证**。硬路由是模型内部的
   专家查表机制；API 是黑盒生成，无法控制内部专家。原实验一实际验证的是
   “CNBE 结构字段作为上下文提示能否提升 API 下游任务”，应如实表述。
2. **对照组设计不严谨**。原计划对照组只给“原文”，实验组多了结构信息，
   无法区分是“CNBE 信息”还是“任何附加结构信息”起作用。
   本次实验增加 **Unicode 码位提示** 作为等量非 CNBE 对照。

## 二、实验设计（修正版）

| 实验 | 样本 | 分组 |
|---|---|---|
| 句读 F1 | 10 条 eval | 原文 / CNBE 字段提示 / Unicode 码位提示 |
| 形近字消歧 | 30 条语料片段 | 原文 / CNBE 字段提示 / Unicode 码位提示 |

## 三、结果

| 任务 | 原文 | CNBE 提示 | Unicode 提示 |
|---|---:|---:|---:|
| 句读 F1 | **0.8472** | 0.8348 | 0.6544 |
| 形近字纠正准确率 | 0.6000 | **0.9333** | 0.7667 |

## 四、结论

1. **CNBE 结构字段对字符级任务有明显收益**：形近字消歧从 0.60 提升到
   0.93（+33.3pp），且显著高于 Unicode 码位提示（0.77），说明收益来自
   CNBE 的部首/结构/笔画字段，而不是“附加信息”本身。
2. **CNBE 提示对语义级任务（句读）无帮助甚至略降**：0.847 -> 0.835，
   与本地“结构路由利于字段任务、不利于语言建模”的结论一致。
3. **对 A100 训练决策的意义**：
   - 建议把 CNBE 结构字段用于字符消歧、形近字修正、字段路由；
   - 不建议把 CNBE 提示用于句读/语言生成；
   - A100 训练决策应基于真实 MoE 对比（本地已证明硬路由 + 三字段映射
     在 64 专家上 Gini 0.15），API 消融仅作为辅助证据。
