# D:/古籍 PDF 语料化方案

日期：2026-08-19  
来源：`D:\古籍`

## 1. 现状

- PDF 数量：316；
- 总大小：约 46.49GB；
- 主要来源：
  - 永乐大典散本：302 个，约 44.64GB；
  - 大明会典内府刻本：8 个，约 1.18GB；
  - 根目录：6 个，约 0.68GB，含资治通鉴、GB 标准、字典等。

## 2. 抽样检查

| 文件 | 页数 | 文字层 |
|---|---|---|
| 资治通鉴（中华书局繁体原版） | 9691 | 无 |
| 大明会典内府刻本.01 | 645 | 无 |
| 永乐大典卷981 | 70 | 无 |
| GB+18030-2022 | 803 | 有 |
| GB/T 30539-2025 | 59 | 有 |

结论：古籍主体是扫描件，不能直接提取文字，必须 OCR。

## 3. 目标

建立可复现的“古籍 PDF -> OCR -> 真值库 -> CNBE 编码 -> 训练语料/评测集”管线。

## 4. 管线

```text
PDF
 -> PyMuPDF 页面提取
 -> OCR（PaddleOCR / deepseek-ocr）
 -> OCR 候选 + 版面
 -> CNBE 覆盖检查
 -> 真值库 / 人工校对
 -> 清理文本
 -> CNBE 编码
 -> corpus manifest + SHA
```

## 5. 优先级

1. 先用已有的永乐大典 70 页真值库完成端到端 pilot；
2. 扩展到永乐大典 302 个 PDF；
3. 再做大明会典 8 个 PDF；
4. 资治通鉴作为大样本扩展。

## 6. 交付

- `manifest.json`：全部 PDF 清单；
- 页面提取脚本；
- OCR 批处理脚本；
- 真值校对工具；
- CNBE 编码脚本；
- 质量报告。

## 7. 注意

- 扫描件 OCR 成本高，先小规模验证再批量；
- 版权与来源需要记录；
- 输出语料不直接进入 GitHub，只提交去敏清单和脚本。
