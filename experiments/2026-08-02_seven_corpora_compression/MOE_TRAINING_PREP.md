# CNBE 七语料实验结果总结与 MoE 训练准备

## 1. 已完成实验总览

七类语料已完成 CNBE 编码、压缩、Volume 随机访问、MoE 路由代理、DeepSeek V4 API
复现五组实验，累计 24,381,237 个中文字符。

关键结论：

1. gzip 仍是纯压缩最优；CNBE 的价值在字段级预测、结构检索和 O(1) 随机访问。
2. CNBE Volume 在全语料上保持约 0.001 ms 的 seek 与按页解压能力。
3. CNBE 结构-专家映射的 FLOPs 加速恒等于 E/m（16 专家、Top-2 路由即 8.0x），
   且 16 专家负载近似完全均衡。
4. 路由代理任务中，CNBE 查表路由准确率 74%-84%，远高于线性学习路由的 6%-8%。
5. DeepSeek V4 API 可复现句读任务，但专家编号一致性仅 0%-15%，不能作为
   MoE 专家标签的来源。

## 2. 实验结果对 MoE 训练的含义

### 2.1 可用的“先验标签”

`(radix, strokes, struct)` 三元组可以生成确定性的专家映射。step1 的负载均衡映射表
已经在七语料上验证：16 专家 Gini 全部接近 0，说明 CNBE 结构字段足以作为
MoE 路由的监督标签，不需要让模型从零学专家分配。

### 2.2 必须区分“路由代理”和“真实 MoE 质量”

现有 74%-84% 是“结构标签代理任务”准确率，不等同于真实 MoE 下游质量。训练真实
MoE 后必须用三项硬指标验收：

- 同参数量 dense 基线 vs MoE 的 next-token loss / perplexity；
- 路由专家负载基尼系数（训练中应稳定在 0.05 以下）；
- 下游任务（古籍句读 F1、结构分类）是否随路由生效而提升。

### 2.3 FLOPs 加速不是墙钟加速

8.0x 是路由矩阵的 FLOPs 理论加速。当前本地基准中实测时间加速约 0.9-1.2x，
瓶颈是内存带宽和专家前向。训练与推理时要以真实吞吐为准，不要直接用 E/m 宣发。

### 2.4 数据质量分层

句读 F1 在 0.48-0.85 之间波动，说明语料类型与 OCR 噪声对语义任务影响显著。
诗集 OCR 语料噪声最高，训练混合数据时应降权或单独作为 domain 采样，避免污染
通用语言建模目标。

## 3. 训练 MoE 的准备清单

### 3.1 数据资产（已具备）

- 七语料 `*.chars.txt`、`*.cnbe`、`*.cnbev`、`templates.json`；
- 每语料 `struct_expert_map_16.json` 与 `struct_expert_map_64.json`；
- 每语料 `routing_benchmark.json`、`routing_quality.json`；
- `cnbe32.db`（8,105+ 字标准库，实际 21,178 行含扩展字符）。

### 3.2 生成训练集

每个 token 的监督标签：

```text
input:  [radix, strokes, struct, domain_id, char_id]
label:  expert_id (来自 struct_expert_map)
```

建议输出 `moe_train.jsonl` / `moe_eval.jsonl`，字段：

```json
{"char": "詩", "cnbe": 123456, "radix": 149, "strokes": 12,
 "struct": 1, "domain": "poetry", "expert": 7}
```

按语料分层划分 train/eval，禁止随机打乱后跨域混入测试。

### 3.3 架构与路由设计

- 起步规模：8-16 experts、Top-2 路由、总参数 1.5B 以内，适配 8GB 显存；
- 路由输入：CNBE 字段向量 `[radix, strokes, struct, domain]`，比纯 token embedding
  更稳定，且天然具备 O(1) 查表后备；
- 训练目标：next-token loss + aux load-balancing loss + 路由标签监督 loss；
- 冷启动：用 step1 映射表初始化路由头的分类权重，再联合训练。

### 3.4 算力策略

- RTX 4060 Ti 8GB：先用 4-bit QLoRA 微调小 MoE；
- 先训“路由分类头 + 小 MLP”验证标签可学性，再扩展到完整 MoE；
- 若全参 MoE 放不下，按 expert 分组 LoRA，路由头全参冻结；
- DeepSeek V4 API 仅用于句读/结构验证，不参与专家标签生成。

### 3.5 验收指标

| 指标 | 目标 |
|---|---:|
| 路由标签训练准确率 | >= 95%（映射表可 100%，此处验证模型是否学会） |
| 专家负载 Gini（训练中） | <= 0.05 |
| MoE vs Dense 同参数量 PPL | MoE 更低或持平 |
| 古籍句读 F1 | 至少不劣于 dense 基线 |
| 路由 FLOPs 加速 | E/m（理论），实际吞吐单独报告 |

## 4. 建议的下一步

2. 写 `train_router_head.py`：小分类头验证 CNBE 字段到专家的可学习性；

4. 训练后跑七语料验证，与现有 74%-84% 代理基线和 dense 基线对比；
5. 将结果沉淀为新一轮白皮书。
